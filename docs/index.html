Teaching RAG, from scratch

一个能离线运行、可评估、带引用的教学版 RAG 工程

这页把项目里的入口脚本、核心函数、数据流和评估链路串起来。 你可以沿着箭头理解：原文如何变成 chunk，chunk 如何进入索引，问题如何变成答案，答案如何被评估。

ingest→normalize→chunk→embed→index→retrieve→fusion→rerank→generate→eval

核心数据结构

Document

原始文档对象，保存全文、来源路径和元信息。它是 chunk 前的输入。

doc_id, text, source_path, metadata

Chunk

检索的最小单位。每个 chunk 都能追溯到章节、段落和字符位置。

chunk_id, chapter_index, start_char, end_char

Evidence

被选入上下文的证据，包含 chunk 文本、分数和来源信息。

chunk_id, text, score, chapter

Answer

最终回答对象，包含答案文本、证据列表、引用和 prompt 元数据。

question, answer, evidences, citations

Phase 2：Ingest / Normalize / Chunk

入口：scripts/prepare_chunks.py

  1. read_text_file()

    读取 .txt / .md，使用 utf-8-sig 兼容 BOM。

  2. normalize_text()

    统一换行、去 BOM、压缩空白，保留章节和段落结构。

  3. Document(...)

    把清洗后的全文包装成文档对象。

  4. chunk_document()

    段落优先切块，支持 chunk_size 和 overlap。

  5. write_jsonl()

    输出 chunks.jsonl，每行一个可检索 chunk。

prepare_chunks.py
  → read_text_file()
  → normalize_text()
  → Document()
  → chunk_document()
      → split_paragraphs()
      → detect_chapter()
      → _tail_overlap_paragraphs()
      → _split_long_paragraph()
  → write_jsonl()

Phase 3：Embedding / Dense Index

FakeEmbedding

完全离线、确定性的 hash embedding。它把字符、bigram 和英文数字词映射到固定维度，再做 L2 normalize。

DenseIndex

保存 vectors 和 chunks。优先使用 FAISS 的 IndexFlatIP，没有 FAISS 时退回 numpy cosine。

build_index.py
  → read_jsonl(chunks)
  → FakeEmbedding.embed_texts()
  → DenseIndex.build()
  → DenseIndex.save()

query_dense.py
  → DenseIndex.load()
  → FakeEmbedding.embed_query()
  → DenseIndex.search()

Phase 4 + 5：Hybrid Retrieval / Rerank

检索链路

  1. DenseIndex.search()

    用向量相似度召回语义/词面近似候选。

  2. BM25Index.search()

    用词项频率和 IDF 做稀疏检索，补强精确匹配。

  3. reciprocal_rank_fusion()

    用 RRF 融合两个候选列表，不直接相加不同尺度的分数。

  4. heuristic_rerank()

    根据 query coverage 和 sources bonus 重新排序。

question
  → embed_query()
  → DenseIndex.search()
  → BM25Index.search()
  → reciprocal_rank_fusion()
  → heuristic_rerank()

Phase 5 + 6：Context / Prompt / LLM

DummyLLM

离线证据摘句器。证据不足时回答“不知道”，每条句子强制附带 [chunk_id]。

OpenAICompatibleLLM

读取环境变量，调用 chat/completions 兼容接口。适合接入 gpt-4o 或其他兼容模型。

answer_question()
  → build_context()
      → Evidence(...)
  → build_prompt()
  → llm.generate()
  → collect citations
  → Answer(...)

Phase 7：Evaluation

Retrieval

Recall@k、MRR、nDCG@k、latency avg / p50 / p95。

Generation

KeywordJudge 或 LLMJudge 判断答案是否正确。

Grounding

检查 citation 是否有效，以及 claim 是否被 evidence 支持。

run_eval.py
  → retrieval_eval()
      → retrieve()
      → ndcg_at_k()
      → latency_stats()
  → generation_grounding_eval()
      → answer_question()
      → Judge.score_answer()
      → Judge.score_support()
  → build_report()
  → eval_report.md
