1. RAG 到底在做什么

RAG 是 Retrieval-Augmented Generation，直译是“检索增强生成”。它解决的问题是： 大模型不可能把你本地的书、文档、业务资料都记在参数里，所以我们先从资料库里找证据， 再把证据交给模型回答。

检索 Retrieval

用户问问题时，系统先去资料库里找最相关的 chunk。这里会用 dense 检索、BM25 检索和 RRF 融合。

增强 Augmentation

把检索到的 chunk 变成带引用的上下文。引用格式是 [chunk_id]，后续可以追溯来源。

生成 Generation

LLM 只能基于证据回答。证据不足时要说“不知道”，不能随便编。

2. 全链路地图

从原始《红楼梦》文本到最终回答，项目走的是下面这条路线。

3. 四个核心数据结构

初学者最容易迷路的地方是“数据到底长什么样”。这个项目只用四个核心数据结构贯穿全链路。

Document

原始文档，代表一整本书或一个文件。chunk 之前先有 Document。

Document(
  doc_id="hongloumeng",
  text="清洗后的全文",
  source_path="orig_txt/hongloumeng.txt",
  metadata={...}
)

Chunk

检索的最小单位。每个 chunk 都带章节、段落、字符位置。

Chunk(
  chunk_id="hongloumeng:00051",
  chapter="第三回 ...",
  chapter_index=2,
  start_char=...,
  end_char=...
)

Evidence

进入上下文的证据。它来自 chunk，但额外带检索分数和来源信息。

Evidence(
  chunk_id="...",
  text="证据文本",
  score=0.73,
  metadata={"sources": ...}
)

Answer

最终回答对象。它保存答案、证据、引用和 prompt 调试信息。

Answer(
  question="...",
  answer="- ... [chunk_id]",
  evidences=[...],
  citations=[...]
)

4. 文本处理：从 txt 到 chunks.jsonl

入口命令：

python scripts/prepare_chunks.py --input orig_txt/hongloumeng.txt --out rag_tutor/data/chunks.jsonl
  1. read_text_file(path)

    读取 txt/md 文件。使用 utf-8-sig，这样带 BOM 的文本也能正常读。

  2. normalize_text(text)

    统一换行、清理 BOM、把全角空格变普通空格、压缩多余空行。它不会删除章节标题，因为后面 citation 要靠章节定位。

  3. Document(...)

    把清洗后的全文包装成一个文档对象，记录原始路径和字符数。

  4. chunk_document(document, chunk_size, overlap)

    按段落优先切块。能不硬切就不硬切，尽量保持自然段完整。

  5. write_jsonl(out, chunks)

    每行写一个 chunk，方便后续流式读取和调试。

chunk_document 内部发生了什么

chunk_document()
  → split_paragraphs()
      → detect_chapter()
  → 逐段合并，直到接近 chunk_size
  → _tail_overlap_paragraphs()
  → _split_long_paragraph()
  → Chunk(...)
初学者重点：chunk 不是随便切字符串。好的 chunk 要兼顾长度、语义完整性和来源追踪。

5. 向量索引：从 chunks 到 dense index

入口命令：

python scripts/build_index.py --chunks rag_tutor/data/chunks.jsonl --out-dir rag_tutor/index/dense
  1. read_jsonl(chunks)

    读取 Phase 2 生成的 chunk 列表。

  2. FakeEmbedding.embed_texts(texts)

    离线 embedding。把字符和 bigram hash 到固定维度，再做 L2 normalize。它不是语义模型，但足够教学和离线演示。

  3. DenseIndex.build(chunks, vectors)

    把 chunk 和向量绑定在一起。

  4. DenseIndex.save(out_dir)

    保存 vectors.npy、chunks.jsonl、meta.json，如果有 FAISS 还会保存 faiss.index。

为什么 normalize 后可以用内积

DenseIndex 里会把向量都做 L2 normalize。归一化后，两个向量的 inner product 就等价于 cosine similarity。 所以 FAISS 用 IndexFlatIP 就能做余弦检索。

6. 混合检索：Dense + BM25 + RRF

入口命令：

python scripts/query_hybrid.py "黛玉进入荣府 贾母"

DenseIndex.search()

把 query 变成向量，然后找向量空间里最相似的 chunk。适合召回“说法接近”的内容。

BM25Index.search()

用词频、文档频率和长度归一化打分。适合召回“关键词完全命中”的内容。

reciprocal_rank_fusion()

只看排名，不直接相加分数。因为 dense 分数和 BM25 分数不是同一量纲。

question
  → FakeEmbedding.embed_query()
  → DenseIndex.search()
  → BM25Index.search()
  → reciprocal_rank_fusion({"dense": dense, "bm25": bm25})
  → hybrid candidates

RRF 的直觉

如果一个 chunk 同时被 dense 和 BM25 排在前面，它就应该更可信。 RRF 给每个候选加上 1 / (rrf_k + rank)，排名越靠前，加分越多。

7. 生成答案：从候选 chunk 到带引用回答

入口命令：

python scripts/ask.py "黛玉进京后拜见了谁"
  1. heuristic_rerank()

    根据 query coverage 和 sources bonus 重新排序。query 词覆盖越多、dense 和 BM25 都命中的 chunk 越靠前。

  2. build_context()

    去重、限制长度，把 chunk 包装成 Evidence，并生成带 [chunk_id] 的上下文。

  3. build_prompt()

    写清规则：只能基于证据回答，不知道就说不知道，每条结论必须引用。

  4. llm.generate()

    默认使用 DummyLLM，真实模型可切到 OpenAICompatibleLLM。

  5. Answer(...)

    收集 answer、evidences、citations 和 prompt 元数据。

answer_question()
  → build_context()
  → build_prompt()
  → DummyLLM.generate()
  → collect citations
  → Answer(...)
初学者重点：RAG 的“可信”不是因为模型厉害，而是因为每条结论都能追溯到 evidence。

8. 评估系统：怎么知道 RAG 好不好

入口命令：

python eval/run_eval.py

Retrieval Eval

看证据有没有找对。指标包括 Recall@k、MRR、nDCG@k、latency avg/p50/p95。

Generation Eval

看答案是否正确。离线用 KeywordJudge，有 key 时可以用 LLMJudge。

Grounding Eval

看答案里的 claim 是否真的被 citation 对应的 evidence 支持。

run_eval.py
  → retrieval_eval()
      → retrieve()
      → ndcg_at_k()
      → latency_stats()
  → generation_grounding_eval()
      → answer_question()
      → Judge.score_answer()
      → Judge.score_support()
  → build_report()
  → eval_report.md

指标怎么读

指标含义低了说明什么
Recall@ktop-k 里是否有相关证据检索召回不够
MRR第一个相关证据排得多靠前排序不够好
nDCG@k高相关证据是否排在前面rerank 或融合需要调
citation accuracy引用是否有效且相关生成或证据选择有问题
unsupported claim rate结论是否缺少证据支撑模型在编或引用不准

9. 一次问答的完整追踪

问题：

黛玉进京后拜见了谁
第 1 步：ask.py 接收问题

解析参数，加载 dense index，选择 FakeEmbedding 和 DummyLLM。

第 2 步：dense 检索

问题被 embed 成向量，DenseIndex.search 找出向量相似的 chunks。

第 3 步：BM25 检索

BM25 根据“黛玉、进京、拜见、贾母”等词面信号召回 chunks。

第 4 步：RRF 融合

dense 和 BM25 的排名被合并，同一 chunk 被多路召回会更靠前。

第 5 步：rerank

heuristic_rerank 根据 query coverage 再排序，选出最终证据。

第 6 步：context + prompt

证据被拼成带 [chunk_id] 的上下文，prompt 要求只基于证据回答。

第 7 步：生成 Answer

DummyLLM 摘出证据句，输出“黛玉进京，初入荣国府，拜见外祖母贾母。 [chunk_id]”。
